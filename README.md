## Модуль предобработки

### Назначение

Модуль предобработки решает задачу приведения разнородных учебных материалов к единому структурированному виду, пригодному для автоматической генерации тестов. Он принимает на вход лекции в форматах PDF, DOCX, TXT, MP3 и MP4, извлекает текстовое содержимое (для аудио и видео — с помощью транскрипции речи), выполняет очистку и нормализацию, выделяет математические формулы и блоки программного кода, разбивает материал на смысловые блоки (чанки) и обогащает их метаданными (тема, ключевые слова, статистика). Результат работы модуля — JSON‑файл, который передаётся генератору тестов на основе GigaChat. 

### Архитектура и компоненты

Модуль построен по конвейерному принципу: каждый этап обработки реализован отдельным классом, а центральный компонент `LectureProcessingPipeline` последовательно вызывает их и передаёт промежуточные результаты. 

Основные компоненты и их роли:

- **`LectureProcessingPipeline` (pipeline.py)** – центральный класс, реализующий полный цикл обработки. Хранит настройки (тип разбиения, размеры чанков, параметры моделей) и по шагам вызывает все остальные модули. Наружу отдаёт объект `ProcessingResult`, на основе которого создается финальный JSON-файл.

- **`file_loader.py`** – загрузчики файлов. Содержит абстрактный класс `FileLoader` и конкретные реализации для каждого формата:
  - `TxtLoader` – загрузка `.txt` с автоматическим определением кодировки.
  - `PdfLoader` – извлечение текста из `.pdf` с помощью **pymupdf4llm**. Включён OCR (опция `use_ocr=True`) для распознавания текста и формул, даже если они представлены в виде изображений. Результат возвращается в формате Markdown, формулы обёрнуты в LaTeX.
  - `DocxLoader` – извлечение текста из `.docx` (включая таблицы).
  - `AudioLoader` – транскрипция `.mp3` с использованием **faster‑whisper** (модель `small` по умолчанию, настраивается).
  - `VideoLoader` – извлечение аудиодорожки из `.mp4` через `ffmpeg` и последующая транскрипция тем же `faster‑whisper`.
  - `FileLoaderFactory` – автоматически выбирает нужный загрузчик по расширению файла.

- **`text_normalizer.py`** – очистка и нормализация текста: удаление невидимых символов, унификация переносов строк, нормализация пробелов. Может сохранять плейсхолдеры формул, чтобы не повредить их при очистке.

- **`formula_extractor.py`** – обнаружение математических формул. Поддерживает LaTeX‑разметку (`$...$`, `\[...\]`) и эвристический поиск plain‑text формул (с греческими буквами, операторами, индексами). Найденные формулы заменяются устойчивыми плейсхолдерами `[[FORMULA_0]]`, не зависящими от позиций, что гарантирует корректное восстановление после разбиения на чанки.

- **`code_extractor.py`** – выделение блоков программного кода. Распознаёт как явные блоки (Markdown‑разметка с тройными кавычками), так и строки с ключевыми словами, операторами и характерными отступами. Код также временно заменяется плейсхолдерами и восстанавливается после разбиения.

- **`text_splitter.py`** – разбиение текста на чанки. Содержит несколько стратегий, включая классические (`ParagraphSplitter`, `SemanticSplitter`, `FixedSizeSplitter`, `MixedSplitter`) и новую, созданную в рамках научной работы: **`SemanticEmbeddingSplitter`** – иерархическая кластеризация предложений на основе эмбеддингов (модель `paraphrase-multilingual-MiniLM-L12-v2`). 

- **`text_cleaner.py`** – удаление нерелевантных фрагментов, характерных для устной речи (приветствия, «вопросы есть?», «перейдём к следующей теме» и т.п.). Применяется к результатам транскрипции аудио/видео.

- **`metadata_extractor.py`** – извлечение метаданных из готовых чанков: определение темы (по ключевым словам), сбор статистики (слов, предложений, лексического разнообразия) и выделение ключевых слов. 

- **`data_models.py`** – датаклассы, описывающие структуры данных, которыми обмениваются компоненты: `TextChunk`, `ProcessingResult`, `ProcessingStats`, `Formula`, `BlockType` и другие.

`Pipeline` вызывает компоненты модуля как отдельные шаги, а данные передаются в виде описанных в `data_models.py` объектов.

### Входные и выходные данные

**Вход**
Модуль принимает файлы пяти форматов:
- `.txt` – текстовый документ;
- `.pdf` – PDF‑документ;
- `.docx` – документ Word;
- `.mp3` – аудиозапись;
- `.mp4` – видеозапись (будет извлечена звуковая дорожка).

Для аудио и видео текст получается автоматической транскрипцией речи (faster‑whisper), для PDF – комбинированным извлечением (pymupdf4llm с OCR).

**Выход**
Результат – JSON‑файл. В нём есть две основные части:
- общая информация: путь к исходному файлу, время обработки, общее число чанков и формул;
- массив `chunks` – список смысловых блоков, на которые разбит материал. У каждого блока есть обработанный текст, найденные формулы, тип блока (текст/код) и метаданные (тема, ключевые слова, статистика).

Этот JSON напрямую читается генератором тестов.

### Стратегии чанкинга в пайплайне

После извлечения и очистки текст нужно разбить на смысловые блоки. В модуле это делает компонент `text_splitter`. Доступно пять стратегий, выбор задаётся или параметром `splitter_type` при вызове `process_file`, по умолчанию `semantic_embedding`.

- **`paragraph`**
  Каждый абзац становится отдельным чанком. Минимальный чанк – один непустой абзац.

- **`semantic`**  
  Объединяет соседние абзацы на основе пересечения длинных ключевых слов (эвристика, без нейросетей). 

- **`fixed_size`**  
  Текст нарезается на блоки примерно одинакового размера в символах. Между блоками можно настроить перекрытие. 

- **`mixed`**  
  Сначала разбиение на абзацы (как в `paragraph`), затем объединение соседних абзацев по семантическому принципу (как в `semantic`).

- **`semantic_embedding`** (новая стратегия, реализована в рамках научной работы)  
  Разбивает текст на предложения, строит плотные векторные представления (эмбеддинги) с помощью модели `paraphrase-multilingual-MiniLM-L12-v2`, затем применяет иерархическую агломеративную кластеризацию с ограничением соседства. Это позволяет группировать предложения в тематически связные блоки, не разрывая естественный порядок. Количество кластеров определяется динамически (по умолчанию `число_предложений / 4`). Результаты кластеризации компактны и семантически осмыслены, что подтверждено в эксперименте.

Размер чанков регулируется параметрами `--min-chunk` и `--max-chunk` (в символах). По умолчанию 100 и 2000. Это позволяет избежать слишком мелких или чрезмерно больших кусков.


## Исследование методов сегментации учебного текста

### Постановка задачи

Первоначально в модуле предобработки применялось разбиение по абзацам.
Для структурированных текстовых документов этого хватало, однако при
добавлении поддержки аудио и видео возникла проблема: расшифровки
устной речи не содержат абзацного деления, и простой метод переставал
работать.

Целью данного этапа работы стал поиск и обоснование метода
автоматической сегментации, который удовлетворял бы двум требованиям:
не опираться на визуальную разметку документа и формировать блоки,
обладающие смысловой целостностью и достаточные для генерации
осмысленного тестового вопроса. Метод должен быть применим к
русскоязычному учебному и научно‑популярному тексту.

Гипотеза, проверявшаяся в эксперименте, заключалась в том, что
векторные представления предложений вместе с иерархической
кластеризацией, в которой учитывается порядок предложений, дадут
более точные границы смысловых блоков, чем известные лексические
подходы и простые пороговые правила.

### Данные и их подготовка

Эксперименты проводились на открытом наборе данных
**RuTextSegNews** ([ссылка](https://huggingface.co/datasets/mlenjoyneer/RuTextSegNews)),
содержащем русскоязычные новостные статьи с ручной разметкой границ
тематических фрагментов. Разметка имеет вид последовательности меток:
`0` — предложение продолжает текущий блок, `1` — начинается новый
блок. На основе этих меток строились эталонные разбиения.

Чтобы ускорить обработку, из полного тренировочного набора (около 20 000
документов) было случайно отобрано 10 000 документов. Полученная
выборка была разделена на три непересекающиеся части:

- **train_logreg** (70%, ≈7 000 документов) — для обучения логистической
  регрессии;
- **train_factor** (30%, ≈3 000 документов) — для подбора гиперпараметров
  предлагаемого метода (коэффициента α и модели эмбеддингов);
- **test** (≈4 000 документов из исходного тестового сплита) — для
  финального сравнения всех методов.

Для каждого документа вычислялись эмбеддинги предложений двумя моделями:
`paraphrase-multilingual-MiniLM-L12-v2` (**MiniLM**) и
`cointegrated/rubert-tiny2` (**RuBERT‑tiny2**). Обе модели доступны
через библиотеку `sentence-transformers`. Все промежуточные результаты
сохранены в отдельных JSON‑файлах, а для обучения регрессии подготовлен
файл `boundary_train_data.npz` с признаками пар предложений
(конкатенация векторов, их разность и косинусное сходство).

Тестовая выборка, на которой получены все финальные результаты,
содержит около 4 000 документов; длина текстов варьируется от 5 до 50
предложений.

### Подбор гиперпараметров предлагаемого метода

Предлагаемый метод опирается на два ключевых параметра: модель
эмбеддингов и коэффициент α, определяющий число блоков по формуле
`k = max(2, ⌊N / α⌋)`, где `N` — количество предложений в документе.
Чем меньше α, тем больше блоков будет выделено.

Чтобы выбрать оптимальную комбинацию, на отложенной выборке
`train_factor` была проведена 5‑кратная кросс‑валидация по документам.
Перебирались значения α от 2 до 8 и обе модели эмбеддингов. Для каждой
комбинации оценивались:

- **Boundary F1** (основная целевая метрика);
- **Pk** и **WindowDiff** (структурные метрики);
- **Intra Similarity** (внутренняя однородность блоков);
- **относительный размер блока** — средняя доля предложений, попадающих
  в один блок (позволяет судить об информативности).

Результаты кросс‑валидации показали:

- MiniLM стабильно превосходит RuBERT по всем метрикам точности;
- максимум Boundary F1 достигается при α = 2 (F1 ≈ 0.529), однако
  при таком α блоки получаются слишком мелкими (в среднем около 2.8
  предложения), что затрудняет генерацию осмысленного тестового вопроса;
- при α = 4 относительный размер блока возрастает до ≈4.7 предложения,
  а F1 снижается незначительно — до 0.498;
- дальнейшее увеличение α ведёт к падению точности без существенного
  выигрыша в размере блоков.

Таким образом, для итогового сравнения с аналогами зафиксированы
**модель MiniLM и α = 4** как компромисс между точностью сегментации
и практической пригодностью блоков для генерации учебных заданий.

### Исследованные методы

В сравнительный анализ вошли девять методов, разделённых на три
группы.

**Простые (базовые) подходы**

- **По абзацам** — каждый непустой абзац становится отдельным блоком.
- **Фиксированный размер** — текст разбивается на блоки примерно
  одинаковой длины с учётом границ предложений.
- **Ключевые слова** — соседние абзацы объединяются, если доля
  пересекающихся длинных слов превышает 0,3.

**Методы, использующие векторные представления**

- **Жадное наращивание (MiniLM)** — граница ставится между
  предложениями, если косинусное сходство их эмбеддингов ниже 0,5.
- **Иерархическая кластеризация (MiniLM, истинное число блоков)** —
  агломеративная кластеризация с косинусным расстоянием и
  ограничением связности; число кластеров равно истинному количеству
  блоков. Служит ориентиром верхней границы качества.
- **Иерархическая кластеризация (RuBERT, истинное число блоков)** —
  тот же алгоритм, но на эмбеддингах RuBERT‑tiny2.
- **Предлагаемый метод** — иерархическая кластеризация с
  автоматическим выбором числа блоков по правилу
  `k = max(2, ⌊N / 4⌋)` (модель MiniLM, параметр α = 4 выбран
  на предварительном этапе кросс‑валидации). Истинное количество
  блоков не используется.

**Метод с учителем**

- **Логистическая регрессия** — модель, обученная на `train_logreg`
  предсказывать границу между предложениями по вектору признаков
  (конкатенация эмбеддингов, разность, косинусное сходство).
  Порог для принятия решения — 0,5.

Все не‑обучаемые методы применялись к тестовым документам независимо;
логистическая регрессия обучалась на выделенном наборе `train_logreg`
и тестировалась на тех же 4 000 документов, что и остальные методы.

### Метрики качества

Пусть документ состоит из `n` предложений. Истинные границы
представлены бинарным вектором `b ∈ {0,1}^{n−1}`, где `b_i = 1`,
если между предложениями `i` и `i+1` проходит граница смыслового
блока. Предсказанный вектор обозначен как `b̂`. Ширина окна для
метрик вычисляется как `k = max(1, ⌊n/20⌋)`.

- **Pk** — доля окон длины `k`, в которых индикатор наличия хотя бы
  одной истинной границы не совпадает с предсказанным:
  `Pk = (1/(n−k)) Σ_{i=1}^{n−k} [ (∃ истинная граница) ≠ (∃ предсказанная граница) ]`.
  Чем ниже значение, тем лучше согласуется крупномасштабная структура.

- **WindowDiff** — средняя абсолютная разность числа границ внутри
  окна:
  `WD = (1/(n−k)) Σ_{i=1}^{n−k} | Σ_{j=i}^{i+k−1} b_j − Σ_{j=i}^{i+k−1} b̂_j |`.
  Метрика штрафует не только за сам факт ошибки, но и за её величину.
  Интерпретируется так же: чем ниже, тем лучше.

- **Boundary F1** — F1‑мера для границ с толерантностью ±1 предложение.
  Граница считается найденной, если предсказанная граница отстоит от
  истинной не более чем на одно предложение. По множествам найденных,
  ложных и пропущенных границ вычисляются точность, полнота и их
  гармоническое среднее. Значение от 0 до 1; чем выше, тем точнее
  найдены границы.

- **Intra Similarity** — среднее косинусное сходство между всеми
  парами предложений внутри одного блока, усреднённое по всем блокам,
  содержащим не менее двух предложений. Показывает семантическую
  однородность блоков; высокое значение свидетельствует о тематической
  связности. Сама по себе метрика не гарантирует правильность границ,
  поскольку излишнее дробление может её искусственно завысить.

### Анализ результатов

Простые методы «По абзацам» и «Ключевые слова» ожидаемо показали
крайне низкие значения Boundary F1 (около 0.036) — они практически не
находят границ в текстах без явного абзацного форматирования. Метод
«Фиксированный размер» демонстрирует чуть лучший результат (0.172),
однако всё равно значительно уступает подходам, учитывающим семантику.

Метод жадного наращивания страдает от избыточного дробления: его
WindowDiff достигает 1.226, что говорит о большом числе лишних границ.
Это подтверждает неэффективность принятия решений о границах на
основе только локального сходства пар предложений.

Наилучшие внешние метрики среди всех методов получены для
иерархической кластеризации с истинным числом блоков на эмбеддингах
MiniLM: Pk = 0.323, Boundary F1 = 0.663. Вариант с RuBERT обеспечивает
самую высокую внутреннюю связность блоков (Intra Similarity = 0.579),
но несколько проигрывает по точности границ. Это объясняется тем, что
русскоязычная модель тоньше чувствует локальную близость и может
«перетягивать» предложения, смазывая объективные границы, проведённые
экспертами.

Предлагаемый метод (α = 4) демонстрирует сбалансированные показатели.
По сравнению с базовым «Фиксированным размером» он повышает Boundary F1
в 2.5 раза (с 0.172 до 0.434), а по сравнению с «По абзацам» — более
чем в 12 раз (с 0.036 до 0.434). Различие с логистической регрессией
по Pk (0.422 против 0.348) статистически значимо — доверительные
интервалы не перекрываются. Отставание от варианта с известным числом
блоков (Pk 0.422 против 0.323, F1 0.434 против 0.663) является
платой за возможность работать без предварительной разметки и с
автоматическим выбором числа сегментов.

Важно отметить, что максимизация точности сегментации (F1) не является
самоцелью. Как показано на этапе подбора гиперпараметров, при α = 2
точность выше (F1 ≈ 0.53), но блоки получаются слишком мелкими для
генерации учебных вопросов. Выбранный α = 4 даёт средний размер блока
около 4.7 предложения, что достаточно для формулировки осмысленного
тестового задания, и при этом сохраняет приемлемую точность (F1 = 0.434).

Логистическая регрессия, обученная на парах предложений, показала
хорошие результаты (F1 = 0.595), однако она требует размеченных данных,
в то время как предлагаемый метод является полностью неконтролируемым
и не нуждается в обучающей выборке. Это делает его более практичным
для реальных сценариев, где разметка отсутствует.

### Выводы

Проведённое исследование показало, что для задачи автоматической
сегментации русскоязычного учебного текста наиболее практичным
является подход на основе иерархической агломеративной кластеризации
эмбеддингов `paraphrase-multilingual-MiniLM-L12-v2` с автоматическим
выбором числа блоков. Подбор гиперпараметров с помощью кросс‑валидации
позволил установить оптимальное значение коэффициента α = 4, которое
обеспечивает компромисс между точностью определения границ (Boundary F1
≈ 0.43) и информативностью получаемых блоков.

Предлагаемый метод превосходит простые эвристики в 12–20 раз по
метрике F1, не требует настройки числа сегментов вручную и не
нуждается в размеченных обучающих данных, в отличие от supervised‑
подходов. Это делает его пригодным для практического применения в
составе конвейера предобработки лекционных материалов, особенно при
обработке расшифровок устной речи, где отсутствует абзацная структура.

Дальнейшее развитие метода может включать более тонкий автоматический
выбор числа кластеров, учёт специфики устной речи и технической
терминологии, а также адаптацию к другим языкам.
